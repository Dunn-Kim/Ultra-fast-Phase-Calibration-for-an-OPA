**구조적 발견 — 축③·④는 판별력이 없다(이미 이론 상한).**
φ* = k·xₙ·u₀ 해석해를 쓰는 한 |AF(u₀)| = N 이 항상 성립 → I(u₀) = EF(u₀)² (동상합 상한),
즉 η_main = 1.000 이 간격과 무관하게 달성된다. 조향 유지 −1.44 dB 도
EF(sin15°)²/EF(0°)² 뿐이라 배열 설계가 아닌 소자 물리(w=1µm 고정)로만 결정된다.
→ 하드웨어 불변 제약 하에서 개선 여지가 있는 축은 ①(사이드로브)·②(시간)뿐.

**축① 내부 상충**: PSLL(최대 사이드로브)과 ISL(사이드로브 총에너지)이 함께 움직이지 않는다.
①트랙 챔피언은 PSLL 최선(−13.66)이나 ISL 1.52로 열위, ① main Opt4 는 ISL 최선(0.77)이나
PSLL −13.27. ② 에서는 **IMP4 가 PSLL·ISL 동시 최선** — 트랙 내 지배적.

### 예산 교정 (2026-07-22) — 41초는 방법의 한계가 아니라 예산 강제의 결과였다

최초 ① 트랙 챔피언은 GA 와 동일 예산(128k 수식 평가 = 64재시작×400ep)을 강제해 41.1s 가
걸렸다. 이는 GA 시간(24.4s)을 초과 — 사용자 기준(시간·세대 모두 GA 미만) 위반.
원인 2가지:
1. **평가 단가**: 경사법은 forward + backward, GA 는 forward 만 → 같은 128k 평가에서
   ①이 1.5~1.7× 비싸다(38~41s vs 24.4s). 예산을 맞추면 구조적으로 진다.
2. **예산 과잉**: 경사법은 훨씬 적은 예산에 수렴한다. 탐색 에포크 축소 실측:

| 탐색 예산 | PSLL | J | 시간 | 세대 | 수식평가 |
|---|---|---|---|---|---|
| 400ep (GA 예산 강제) | −13.66 | −13.37 | 41.1s | 400 | 137,500 |
| 150ep | −13.35 | −12.92 | 17.2s | 150 | 57,500 |
| **30ep (채택)** | **−13.32** | **−12.89** | **5.55s** | **30** | **19,040** |
| 20ep/top-6 | −13.05 | −12.69 | 3.59s | 20 | 11,460 |

예산 6.7× 축소(400→60ep 이하)에도 PSLL 손실은 0.34 dB, 시간은 7.4× 단축.
30ep 지점에서 탐색 2.4s + 연마 2.6s 로 연마가 지배 — 이 아래로는 품질이 꺾인다.
② 트랙도 동일 점검: CMA 250→60세대 시 3.29s 로 줄지만 PSLL −13.21/ISL 1.78 로 열화,
250세대 유지가 유리.

## 구조 정리 + 챔피언 개선 (2026-07-22)

### 정리
공용 로직을 `opt_core.py` 로 추출해 정본화하고, 챔피언 2종만 프로덕션 경로에 남겼다
(`champion_track1.py`, `champion_tandem.py`, `evaluate_champions.py`, `test_opt5.py`).
미채택 실험 7종은 `backlog/` 로 동결 이동 — 부모 경로 부트스트랩이 삽입되어 그대로
실행되며, 산출물은 상위 `results/` 로 통일된다. 이동 후 ① 챔피언 결과 비트 동일 재현,
게이트 9/9 통과 확인.

### 개선: 목적함수에 ISL 항 추가
그동안 두 챔피언 모두 **PSLL(사이드로브 피크) 단독**을 최적화했으나, 평가 기준은
"메인로브 제외 **전부** 최소"였다. 사이드로브 총에너지(ISL)를 미분가능 항으로 만들어
(`soft_isl_per_restart`, Δu 가중 적분) 손실에 더했다.

부작용과 대응: ISL 항은 개구를 좁히려 간격을 하한으로 민다. w_isl=3.0 에서 최소 간격이
2.012µm 까지 밀려 커플링 페널티가 3.1 로 폭증했다. barrier 가중을 올려 상쇄하되,
**판정은 항상 규약 기본 barrier(0.8)로 되돌려** 수행하도록 분리했다 (최적화 압력 ≠ 판정 기준).

| | PSLL | ISL | J | 최소간격 | 개구 | 시간 |
|---|---|---|---|---|---|---|
| ① 개선 전 (w_isl=0) | −13.32 | 0.90 | −12.89 | 2.206µm | 94.5µm | 5.55s |
| **① 챔피언 (w_isl=1.0, b=3.0)** | **−13.35** | **0.56** | **−12.94** | **2.289µm** | **90.7µm** | 6.31s |
| ② 개선 전 (w_isl=0) | −13.37 | 1.26 | −13.02 | 2.258µm | 101.0µm | 0.32s |
| **② 챔피언 tandem (w_isl=0.4, b=2.0)** | **−13.55** | **0.77** | −12.98 | 2.246µm | **95.7µm** | 0.38s |

① 은 PSLL·ISL·J·마진·개구가 **동시에** 개선됐다 (시간 +0.76s). ② 는 PSLL +0.18,
ISL +0.49, 개구 −5.3µm 개선에 J −0.04 의 오차 수준 손실. 두 챔피언 모두 ISL 이
GA(2.33) 대비 3~4배 낮다.

가중 선택 근거: ① 은 단일 사양에 자유도가 커 w_isl=1.0 을 감당하지만, ② 는 한 벌의
가중치로 여러 사양을 동시에 만족해야 해 1.0 에서 PSLL 을 0.31 dB 잃었다 — 0.4 가 균형점.

## 한계 진단과 로버스트·MODE 검증 (2026-07-25)

### 진단: −13.4 dB 는 알고리즘이 아니라 하드웨어의 벽

여러 방법이 −13.2~−13.7 에 수렴한 것이 탐색 실패인지 물리 한계인지 확인했다.

| 검증 | 결과 | 함의 |
|---|---|---|
| 설계각 사이 성능 (1.25° 간격 스캔) | 0°→±15° 단조 하강, 최악은 항상 경계 | 각도 그리드 증강 무의미 |
| 위상 자유도 개방 (φ≠φ*) | 메인로브 무손실 시 +0.02 dB | φ* 해석해가 이미 최적 |
| 위상 + 메인로브 10% 희생 | +0.43 dB | 대가 대비 미미 |
| 진폭 자유도 (하드웨어 변경 가정) | +0.33 dB | 진폭 테이퍼도 답이 아님 |

→ **알고리즘 추가 투자는 수익이 없다.** 남은 것은 실제 성능(오차 내성)과 사양 재정의뿐.

### 오차 민감도 — 챔피언은 날카로운 해에 앉아 있다

몬테카를로 (위치 σ=50nm, 위상 σ=5°, worst-angle PSLL):

| 설계 | 공칭 | 오차 평균 | p90 | 최악 | 손실 |
|---|---|---|---|---|---|
| ① 챔피언 | −13.35 | −11.82 | −11.18 | −10.13 | 1.53 dB |
| GA | −11.17 | −10.50 | −9.86 | −8.39 | 0.67 dB |

공칭 격차 2.18 dB 가 실제 조건에서 1.32 dB 로 줄어든다 — 여전히 우위이나 절반 가까이 잃는다.

### 로버스트 최적화 — 통합했으나 기본값은 아님

`opt_core` 에 오차 규약(NOISE_POS_UM=0.05, NOISE_PHASE_RAD=5°), `perturb`, `mc_psll` 을
추가하고 `run_gradient`/`polish_lbfgs` 에 `robust_k` 를 넣었다.
`champion_track1.py --robust K` 로 사용하며, 이때는 최종 선택 기준도 MC p90 으로 바뀐다
(공칭 J 로 고르면 로버스트 연마의 이득이 선택 단계에서 버려진다).

| 구성 | 공칭 | 오차 평균 | p90 | 최악 | 시간 |
|---|---|---|---|---|---|
| 공칭 최적화 (기본) | **−13.35** | −11.82 | −11.18 | −10.13 | **6.3s** |
| 연마만 로버스트 K=8 | −12.93 | −11.77 | −11.11 | −10.26 | 24.2s |
| 연마만 로버스트 K=24 | −12.93 | −11.85 | −11.31 | −10.30 | 68.9s |
| 탐색까지 로버스트 K=8 | −12.81 | −11.69 | −11.11 | −10.02 | 48.7s |

- **탐색 로버스트화는 역효과** — 노이즈가 경사를 흐려 좋은 분지를 놓치고, 공칭 0.54 dB
  손실이 이득을 상쇄한다. `--robust-explore` 로 재현만 가능하게 두고 기본 비활성.
- 연마만 로버스트하면 p90 +0.13, 최악 +0.18 dB 를 얻지만 시간이 10배. **기본값 불채택**,
  수율·최악 보증이 중요한 사양에서만 옵션으로 사용.
- 이득이 작은 이유: 오차 하 저하의 대부분은 설계 민감도가 아니라 오차 자체의 물리적
  영향이다. 설계로 완화할 수 있는 몫이 애초에 제한적이다.

### 예상 밖 결과 — tandem 이 오차에도 가장 강건

`evaluate_champions.py --mc N` 으로 전 후보를 오차 하에서 재평가한 결과:

| 후보 | 공칭 | 오차 p90 |
|---|---|---|
| ② 챔피언 tandem | −13.55 | **−11.40** |
| ① 400ep (41s) | −13.66 | −11.58 |
| ① 챔피언 (6.3s) | −13.35 | −11.18 |
| ① 로버스트 K=24 (69s) | −12.93 | −11.22 |

tandem 은 명시적 로버스트 최적화 없이도 ① 챔피언보다 오차에 강하다. 한 벌의 가중치로
여러 사양을 동시에 만족해야 하는 제약이 정규화로 작용해 평활한 해를 학습한 것으로 보인다.
→ **② 트랙에는 로버스트 옵션을 추가하지 않았다** (이미 그 효과를 얻고 있음).

### MODE 검증 — 결론은 EF 모델 오차에 견고

현 EF 는 d=3µm 등간격 로그로 적합됐으므로 비등간격에서의 정확도가 미검증이다.
EF 를 흔들어 결론이 뒤집히는지 확인했다:

| EF 변형 | 챔피언 | GA | 격차 |
|---|---|---|---|
| 기준 (MODE 적합) | −13.35 | −11.17 | 2.18 |
| obliquity ×0.5 / ×1.5 | −13.29 / −13.39 | −11.14 / −11.20 | 2.15 / 2.19 |
| g 계수 ×0.8 / ×1.2 | −13.04 / −13.33 | −11.06 / −11.29 | 1.98 / 2.04 |
| 소자폭 0.8 / 1.2µm | −13.09 / −13.33 | −11.08 / −11.29 | 2.01 / 2.05 |
| 보정 제거 (순수 sinc) | −11.28 | −10.27 | 1.01 |

**모든 변형에서 순위가 유지된다.** EF 보정을 통째로 없앤 최악의 경우에도 챔피언이 GA 를
1.01 dB 앞선다 — 설계 결론은 EF 모델 오차에 견고하다.

`mode_validation.py` 신설:
- `--crosscheck` (지금 실행 가능): 기존 로그로 EF 재검증 —
  N=32 적합 R² 0.9964, **N=64 홀드아웃 0.9962, N=128 홀드아웃 0.9966** (소자 수 외삽 견고)
- `--spec`: 랩에서 돌릴 varFDTD 실행 명세 (챔피언 위치 32개, 조향각별 위상표, 관측 격자)
- `--check CSV --angle A`: MODE 결과 대조 → R²·PSLL 오차·합격 판정
  (게이트 R² ≥ 0.95, PSLL 오차 ≤ 1.0 dB; 미달 시 EF 재적합 후 챔피언 재설계)

**남은 미검증은 하나** — 비등간격 배열의 실제 varFDTD 결과. 이 PC 에 Lumerical 이 없어
명세와 대조 도구만 준비했다. 랩에서 3회 실행(0°, ±7.5°, ±15°)이면 판정이 끝난다.

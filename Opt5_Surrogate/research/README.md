# 회차 최소화 챔피언 — `m_round`

**목표:** 특정 장비의 벽시계 속도가 아니라, 연구 장비가 갖춰졌을 때 **가장 적은 반복 회차로 최고 수준의 판정
점수(J)** 에 도달하는 간격 설계 알고리즘. 포스터가 위상 캘리브레이션을 "반복 100회"로 평가했듯이, 여기서도
주 지표는 반복 회차다.

## 결과 한눈에

±15° 5각 프로토콜, N = 32, 시드 8개 (42–49):

| | J 평균 | 최악 | 최선 | 표준편차 | 반복 회차 |
|---|---|---|---|---|---|
| **챔피언 `m_round`** | **−13.552** | **−13.521** | −13.579 | 0.019 | **71** (융합 Newton **47**) |
| 기존 ① 챔피언 레시피 (`champion_track1.py` 구성, 같은 판정으로 8시드 재측정) | −12.45 | −11.89 | −12.95 | 0.32 | — |

융합 Newton 은 사다리 8점의 헤시안을 같은 회차에 계산해 반복당 1회차로 줄인다. 시드 47 실측: 47회차, J −13.583
(비융합 −13.579), 평가량 6.7e6 단위 (비융합의 7배).

챔피언 설계(시드 47, `results/research/final_spacing_champion_round.csv`): PSLL −14.01 dB, J −13.58,
위치 σ 50 nm·위상 σ 5° 오차 하 PSLL p90 −11.46 (기존 ① −11.18, ② −11.37).

## 규약

| 항목 | 정의 |
|---|---|
| 판정 J | θ-격자(1801점) f64 hard worst-angle PSLL + 커플링 페널티(규약 기본 barrier 0.8). 낮을수록 좋음 |
| **반복 회차** | 목적함수를 **배치로 한 번 평가하는 순차 호출 수**. 한 회차 안에서 후보 몇 개를 동시에 평가하든 1회차 — 병렬 폭은 장비가 흡수한다고 본다 |
| 평가량 (단위) | 설계 1개 × 전 각도 × 정밀 격자 순방향 1회 = 1단위, 역전파 포함 3단위. 성긴 격자는 비례 할인. 하드웨어 자원의 대리 지표 |
| 시드 | 42..49. 평균을 주 지표로, 최악·표준편차를 병기 (3시드 평균은 8시드보다 약 0.05 dB 낙관적이었다) |

하네스(`harness.py`)가 회차·단위를 자동 계측하고, 반환된 후보(≤64)를 정밀 판정해 최선 J 를 채택한다.

## 알고리즘

```
탐색 (10회차)   Adam, 후보 1024개, 초기 로짓 분산 0.3, β 0.2→2 어닐링
     ↓          — 거친 지형을 매끈한 목적부터 풀어 좋은 분지로 보낸다
Newton (25회)   후보 전부에 배치 saddle-free Newton: 정확 31×31 헤시안 + λ 사다리 8점 동시 평가
     ↓          — 이차 수렴. 융합 모드는 사다리점의 헤시안까지 같은 회차에 계산 → 반복당 1회차
SLP (10회차)    정밀 v-격자 순위 상위 64개를 판정 θ-격자 hard max 그대로 epigraph LP(신뢰영역)로 연마
                — 판정 목적 자체를 푸는 마무리. 후보 간 독립이라 병렬 → 회차 = 반복 수
```

목적함수의 계산은 v-도메인 엔진(`opt_core.VDomain`)이 맡는다. 조향해 아래서 각도별 배열인자가 W(u − u0) 하나로
모이고, 균등 v-격자에서 W 를 배치 행렬곱으로 분해한다 — 직접 합과 상대오차 2.5e-14 로 같은 **정확한 수식**이다.

## 최고점을 찍는 조건

시드 8개 실측. 회차는 비융합 / 융합.

| 구성 (나머지는 챔피언과 동일) | 회차 | J 평균 | 최악 | 표준편차 |
|---|---|---|---|---|
| **챔피언** (탐색 10 · Newton 25 · SLP 10) | 71 / **47** | **−13.552** | **−13.521** | 0.019 |
| SLP 5회 | 66 / 42 | −13.537 | −13.514 | 0.017 |
| Newton 20회 | 61 / 42 | −13.538 | −13.449 | 0.042 |
| 탐색 5회 (lr 0.12) | 66 / 42 | −13.482 | −13.423 | 0.044 |
| Newton 15회 | 51 / 37 | −13.428 | −13.349 | 0.054 |

조건별 근거 (시드 3개 스윕 포함):

1. **Newton 25회 이상** — 무릎점. 20회면 최악 시드가 0.07 dB, 15회면 평균이 0.12 dB 떨어진다. 35회로 늘려도 +0.007 dB.
2. **후보 1024개 + 초기 분산 0.3** — 약한 시드를 끌어올리는 것은 회차가 아니라 폭과 다양성이다.
   후보 1024·분산 0.1 은 8시드 평균 −13.503 (최악 −13.405), 후보 256 은 −13.465. 분산 0.6 은 과하다 (약한 시드 −13.45).
3. **짧고 큰 걸음의 탐색** — Adam 10회·lr 0.08. lr 0.01 이면 −13.39, 탐색을 5회로 줄이면 −13.48.
4. **판정 목적을 직접 푸는 마무리** — SLP 는 5~10회면 수렴한다 (5회 −13.537, 10회 −13.552, 40회 차이 없음).
5. **목적 가중** — 최적화 중에는 β 2, ISL 0.3, barrier 3. 기존 레시피의 β 3·ISL 1.0 은 J 기준으로 맞지 않았다.
   barrier 를 5로 올려도 개선이 없다.

회차를 더 줄이려면 42회차(SLP 5회)가 손실 0.015 dB 로 가장 싸다. 37회차 이하는 급락한다.

## 다른 방법론 대비 이점

각 방법군은 별도 탐색으로 조율한 최고 구성이다 (`results/research/comparison.json`).
J 는 시드 8개(대규모 obj 는 3개), 회차는 시드 42 실측.

| 방법 | J 평균 | 최악 | 반복 회차 | 평가량 |
|---|---|---|---|---|
| **챔피언 `m_round`** | **−13.552** | **−13.521** | **71 / 47** | 9.5e5 |
| 목적함수 재조정 + 정확 minimax SLP, 대규모 | −13.549 | −13.513 | 2,608 | 1.6e6 |
| 목적함수 재조정 + SLP | −13.493 | −13.438 | 857 | 7.2e4 |
| 진화 메메틱 (L-SHADE/CMA + 행별 L-BFGS) | −13.450 | −13.305 | 4,787 | 1.4e5 |
| 진화 ILS (병렬 반복 국소탐색) | −13.450 | −13.364 | 10,317 | 2.0e5 |
| 베이신 호핑 (MBH + β 연속 마무리) | −13.446 | −13.385 | 7,834 | 2.0e5 |
| 학습 기반 (엘리트 재생 + 흐름 사전분포) | −13.396 | −13.374 | 2,464 | 1.7e5 + 학습 1.95e6 |
| 기준 multistart (Adam → 행별 L-BFGS) | −13.039 | −12.923 | 1,185 | 1.9e5 |

1. **회차** — 동급 이상 품질을 **비융합 71회차 기준 12~145배, 융합 47회차 기준 18~220배 적은 회차**로 낸다. 1차 방법(L-BFGS·Adam)과 진화 계열은
   라인서치 백트래킹·세대가 순차라 회차가 쌓이고, Newton 은 31차원에서 헤시안이 싸서 반복 수 자체가 작다.
2. **최악 시드** — 최악 −13.521 로 모든 방법 중 가장 좋다. 시드 운에 덜 기댄다.
3. **학습 불필요** — 학습 기반은 엘리트 집합 생성에 1.95e6 단위를 먼저 쓰고도 품질이 낮다.
4. **근사 없음** — 서러게이트 없이 정확한 수식으로 탐색하고, 마무리는 판정 목적 그 자체를 푼다.
   서러게이트 착취(gap 3.18 dB, Opt5 README) 같은 위험이 없다.

## 한계

1. **회차 지표는 병렬 장비를 전제한다.** 한 회차에 후보 1024개 × 헤시안(31 HVP), 융합이면 사다리 8배까지 동시
   계산한다. 평가량은 비융합 9.5e5 / 융합 6.7e6 단위로, 최소 평가량 방법(목적함수 재조정 + SLP, 7.2e4)의 13 / 93배다.
   융합의 8192행 헤시안을 한 번에 만들면 중간 텐서가 수 GB 가 되어 MPS 에서 결과가 깨졌다 (J −12.53) —
   1024행 청크로 나눠 계산한다 (`newton(chunk=...)`). 단일 저사양 장비에서
   벽시계 시간이 짧다는 보장은 없다 (M3 Pro, CPU 레인과 경합 상태에서 MPS 약 48 s/시드).
2. **헤시안 비용은 변수 수의 제곱.** N = 32(변수 31)에선 싸지만 N = 128(127)이면 16배다. 미검증.
3. **조향해 위상 전제.** v-도메인 분해는 위상 = 조향해 φ* 일 때 정확하다. 위상까지 최적화하거나 위상 오차를 넣은
   평가는 이 엔진으로 직접 할 수 없다 (소자별 가중치 확장이 필요).
4. **SLP 병렬은 가정이다.** 현재 구현은 후보별 LP 를 CPU 에서 순서대로 푼다. 회차 계상은 병렬 LP 솔버를 가정한다.
5. **ISL 은 희생된다.** 챔피언 ISL 1.53 dB (기존 ① 0.56). 판정 J 에 ISL 이 없어서다. ISL 을 사양에 넣으면 가중을
   다시 조율해야 한다.
6. **전역 최적 증명 없음.** 관측된 최고 J 는 −13.601 (대규모 obj, 시드 43) 로 챔피언 최선 −13.579 보다 0.02 dB
   좋다. 8시드가 0.06 dB 안에 모이지만 남은 여지가 0 은 아니다.
7. **물리 모델 범위.** EF 는 d = 3 µm 등간격 MODE 로그로 적합했다 — 비등간격 정확도는 varFDTD 신규 실행 전까지
   미검증이다 (`mode_validation.py --spec`). 결과는 ±15° 5각·N = 32 사양 기준이며 다른 사양은 재조율이 필요하다.
8. **비교의 공정성.** 다른 방법군은 각 약 45분 탐색으로 조율한 결과다 (전수 탐색 아님). 회차는 시드 42 한 번의 실측이다.

## 재현

```bash
cd Opt5_Surrogate
python research/harness.py run m_round --tier B2 --lanes mps,cpu,cpu --tag champion   # 시드 8개
python research/harness.py run m_round --tier B2 --kw '{"fused": true}' --seeds 47    # 융합 Newton
python research/harness.py board
```

`--lanes` 는 시드를 레인별 프로세스로 나눠 돌린다 (GPU 프로세스는 1개만 두고 나머지는 CPU).
`--tier` B1 = 2e5 / B2 = 2e6 단위 예산 (10% 초과 시 보드에 `!`).
